# Wi-Fi 切换后的服务器路由恢复

以下为 1.1.10 / 助手 5 的设计记录；该版本已经实网确认存在回归。1.1.11 / 助手 6 将服务器路由核对改为 NET_RT_DUMP 完整枚举，避免 RTM_GET 返回作用域缓存时漏掉本次静态路由。更新使用精确 RTM_DELETE + RTM_ADD，读取失败保留清理记录；连接成功须等待脚本完成并核对本次 IPv4、DNS 及路由。最新验证见 VERIFICATION.md。

## 故障依据与确定性

2026-09-06 09:54（App 日志为 UTC 01:54），en0 从 192.168.71.118 / 192.168.71.1 切到 192.168.124.36 / 192.168.124.1。统一日志确认旧连接及后续 11 个新 OpenConnect 进程的 TCP 连接都返回 `EADDRNOTAVAIL`（49）；清理旧隧道后，configd 已将 en0 设为主接口，新进程 DNS 查询成功。09:56 切回原网络后连接成功。因此这次不能继续归因为旧版的幽灵 DNS 服务键。

内核还记录了向 VPN 服务器添加主机路由失败，尝试网关为隧道地址。该日志只展示**正在添加的路由**，不能证明原有路由具体绑定哪个地址。故障时没有 RTM_GET 快照；“旧服务器路由保留旧网关／源地址”是与 errno、切回恢复及脚本行为一致的判断，尚未用真实切网完成闭环验证。

本机 vpnc-script 的隔离重放确认两个缺口：BSD 默认网关选择可先取到隧道默认路由；服务器路由只执行 add，失败仍返回 0。断开时还可能恢复切网前保存的网关，并把空网关交给 route(8) 触发 DNS。助手 4 的原生兜底只覆盖本次 configd 服务键，没有覆盖服务器主机路由。

## 修复机制

- 在 connect、attempt-reconnect、reconnect 钩子中，通过 configd 的物理服务、链路和服务顺序选择 en 接口；再用该接口的作用域 RTM_GET 默认路由核对源地址和网关。两者一致才认为出口可用，不能从 VPN 的全局默认路由猜网关。
- 用数值地址通过 PF_ROUTE 建立或更新到 VPN 服务器的无作用域 IPv4 /32 路由。请求显式带 RTA_IFP 和 RTA_IFA；即使接口仍为 en0，也更新旧源地址。每次修改后重新查询并核对目标、网关、源地址、接口和稳定标志，未通过核对不报告成功。
- 私有 `route.json` 先写修改意图，再写内核，最后保存读回结果。仅修改／删除与本会话记录相符的静态路由。独立存在的静态路由不接管；出口不符时报告冲突。内核自动生成且符合当前物理出口的非静态克隆可替换；清理时不把新生成的缓存当作旧静态路由残留。
- 断开及进程退出后，清理本次 configd 服务键并删除自己的服务器路由，再读回确认。删除不需要可用物理网络或 DNS。修改后、验证前崩溃时可依据预写意图恢复。已有共享会话锁和 PID 检查继续保护活跃助手／脚本，孤儿恢复只处理可独占的会话。
- PF_ROUTE 读取按类型、PID、序号匹配回复，忽略同时到达的接口通知；查询有 1 秒预算。恢复钩子遇到物理出口未就绪时返回非致命结果，留待后续网络恢复，不主动拆掉离线会话。

固定助手入口在私有会话目录生成 vpnc-script 副本，保留安装脚本的接口、DNS 和分流处理。副本覆盖服务器主机路由操作及 IPv4 默认路由保存／恢复函数；默认路由交由本次 configd IPv4 服务管理，删除服务后由 IPMonitor 恢复当前物理出口。全隧道的 Router 和 OverridePrimary 由原生代码写入并读回验证，包括服务端未提供 DNS 的情况。副本禁止 networksetup 将隧道 DNS 写入物理网络的持久设置，避免主接口异步切换时误写。Homebrew 安装文件不改动。

物理离线等待、通知去重、1 秒防抖、3 秒恢复期限与 Auto Connect 策略保持原有行为。这里的出口就绪不代表新 Wi-Fi 已通过门户认证或能访问互联网。

## 本地证据

引擎的每行输出先经脱敏，再独立记录，包含未知错误、DTLS 失败、脚本超时、PID 信号、退出原因、路由修改前后与清理结果。诊断严重级别不直接驱动连接状态。可识别的地址不可用等错误附带 errno；认证字段／正文保留脱敏占位行，超长行有截断提示。

- App：`~/Library/Logs/XD VPN/activity*.jsonl`，4 × 1 MiB。引擎事件带 `diagnostic`，与原有连接 ID、物理网络事件和质量统计共存。
- 助手：`/Library/Logs/XD VPN/helper-<UID>/helper*.jsonl`，4 × 4 MiB，root 私有。先落盘，再转发给 App；App 通道断开后继续记录清理。错误与停止事件执行 fsync。文件写入失败经 App 与系统统一日志明确报告。
- 会话：`/private/var/run/xdvpn-network-<UUID>/` 中的 tunnel.json、route.json 和 lease。它们用于归属与恢复，清理成功后删除；失败时保留并报告接口、键、服务器及路径。

不记录真实密码、Cookie、Token 或认证正文，不增加 HTTP dump，不上传日志。网络地址和进程信息保留用于诊断。

## 验证与边界

回归使用替身路由／动态存储，覆盖换网、同接口换源地址、重复恢复、离线、新克隆、静态路由冲突、内核修改失败／读回失败、删除重试及预写意图崩溃恢复。隔离执行本机安装脚本的 connect／attempt-reconnect／disconnect 流程，路由和 scutil 命令全部为替身，检查不再添加错误主机路由或恢复旧默认网关。真实系统仅执行 configd 和 PF_ROUTE 读取，验证了当前物理出口及源地址查询。

本轮实现针对当前部署的 IPv4 VPN 服务器和 en 物理出口；不新增 IPv6 外层服务器、代理或非 en 物理接口支持。其他 VPN 或旧版留下但没有本助手记录的静态路由不自动删除。本轮没有改动实际网络、使用真实凭据、升级正在运行的助手或验收真实切网；实际 RTM_ADD／CHANGE／DELETE、IPMonitor 默认路由恢复以及内网业务连通性仍需新版运行验收，不能用替身测试替代。

升级应用后需在「系统授权」点击「升级系统助手」安装版本 5。已有专用授权及配置沿用，管理员确认用于替换受保护文件，sudoers 权限范围未扩大。

实现参考：Apple [rtsock.c](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/net/rtsock.c)、[route.c](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/net/route.c) 的 RTM_GET／RTM_CHANGE、作用域及 RTA_IFA 处理，以及 [vpnc-script](https://gitlab.com/openconnect/vpnc-scripts/-/blob/master/vpnc-script)；本机重放记录与事故摘要位于 `.build/incident-20260906-0954-*`，未纳入分发包。
